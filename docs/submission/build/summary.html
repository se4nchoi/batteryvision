Intel Geti · OpenVINO 실습 · 요약

배터리 표면 식별 Vision AI

배터리 셀 사진에서 crack과 scratch를 찾아 PASS · REVIEW · REJECT로 판정하는 객체 탐지 모델

한 줄 요약. Intel Geti로 탐지 모델 3종(ATSS-MobileNetV2, YOLOX-S, YOLOX-Tiny)을 학습해 OpenVINO로 비교했다. 가장 작은 ATSS가 가장 정확했고(테스트 mAP@50 92.9%), INT8 양자화로 CPU 추론이 2–4배 빨라졌다. 하지만 나중에 촬영된 새 세션에서는 결함 셀 검출률이 47%로 떨어져, 이 모델은 학습에 쓴 촬영 환경에 맞춰진 모델임이 확인됐다.

1. 목표

점수 자체보다 공개 데이터셋과 Geti 모델을 조합해 실제로 동작하는 검사 AI를 만드는 것이 목표다. 모델이 결함을 찾으면 신뢰도에 따라 0.60 이상은 불합격(REJECT), 0.30–0.60은 사람 검토(REVIEW), 그 아래는 합격(PASS)으로 판정한다. 가상 검사 라인 대시보드에서 실제 모델로 이 판정을 시연한다.

2. 데이터와 방법

  • 데이터: Roboflow 공개 데이터셋 원본 1,531장, 클래스 crack · scratch. 학습 3,214장(원본 1,072장 ×3 증강) · 검증 306장 · 테스트 153장. 테스트는 Geti에 올리지 않고 따로 평가했다.
  • 데이터 정제: 테스트 153장 중 22장이 학습 사진과 거의 같은 사진(dHash 거리 ≤ 8/256)이어서 빼고 131장으로 평가했다. ATSS mAP@50은 93.3% → 92.9%로 거의 같았다. 같은 촬영 세션이 학습과 테스트에 섞여 있는 문제(153장 중 152장)는 남아 있다.
  • 모델: Geti 템플릿 ATSS-MobileNetV2(3.9M), YOLOX-S(9M), YOLOX-Tiny(5.06M). 각각 FP16, FP16+XAI(heatmap), INT8로 내보냈다.
  • 측정: 같은 131장, 같은 판정 기준. 속도는 Intel Core Ultra 7 265K CPU에서 사진 1장씩, 전처리·후처리 포함 평균.
  • 한계: 모든 사진이 탁상 촬영이며 배경은 초록 매트 · 회색 · 나무 탁상(테스트 131장 기준 39 · 54 · 38장), 셀당 사진 1장이다.

테스트 131장(결함 98 · 정상 33). "놓친 결함 셀"은 검토 기준 0.30 미만으로 통과한 결함 사진 수. crack AP@50은 모든 모델에서 1.000. Geti 보고값(Geti 자체 검증셋): mAP@50 0.878 · 0.841 · 0.798, scratch F1 0.77 · 0.70 · 0.67로 순서가 같다. CPU 시간은 측정마다 수 ms 편차가 있어 FP16 대비 INT8 차이를 기준으로 본다.

  • 작은 모델이 더 정확했다. 파라미터가 가장 적은 ATSS가 가장 정확했다. Geti의 크기별 mAP를 보면 작은 물체에서는 ATSS(0.385)와 YOLOX-S(0.39)가 비슷하고 Tiny(0.246)만 낮아, ATSS의 우위는 중간·큰 결함에서 나온다. 입력 해상도 차이(992×800 vs 640×640)는 아직 검증하지 않은 가설이다.
  • INT8: CPU에서 2.0–4.0배 빠르고 크기는 약 절반, mAP@50은 유지된다. 대신 신뢰도가 조금 낮아져 0.60 기준 박스 재현율이 ATSS 57.7% → 52.0%로 떨어지고, 놓친 결함 셀이 ATSS 0 → 1, YOLOX-S 6 → 8로 늘었다. INT8을 쓰려면 판정 기준값을 다시 정해야 한다.

5. 2차 데이터셋: 새 촬영 세션

같은 작성자가 나중에 촬영한 새 세션 45장(결함 30 · 정상 15, 학습에 쓰지 않음, 기존 데이터와 중복 0건)으로 다시 평가했다.

  • 결함을 다른 결함으로 착각한 것이 아니라, 맞는 위치를 찾고도 점수가 0.06–0.28로 낮아 검토 기준(0.30)에 못 미쳐 통과시켰다.
  • 정상 셀을 자동 불합격시킨 경우는 없다. 촬영 환경이 바뀌었을 때의 실패는 놓침이며, 이는 실제 라인에서 가장 비싼 오류다.

6. 배운 것

  1. 데이터부터 의심하기. 직접 만든 데이터셋이 아니어서 중복 사진과 겹친 촬영 세션이 있었다. 받은 데이터는 학습 전에 먼저 검증한다.
  2. 큰 모델 ≠ 좋은 모델. 1,500장 규모 데이터에서는 가장 작은 ATSS가 가장 정확했다.
  3. 최적화는 기준값과 함께. INT8은 속도와 크기에서 이득이 크지만, 신뢰도 분포가 바뀌므로 판정 기준을 다시 맞춰야 한다.
  4. 점수 ≠ 현장 성능. 92.9%의 테스트 점수가 새 촬영 세션에서는 47% 검출로 떨어졌다.

7. 앞으로 할 일

  • 실제 검사 스테이션에서 찍은 사진으로 재학습하고, 2차 세션 사진을 학습에 추가해 회복 정도를 측정한다.
  • 판정 기준값을 테스트셋이 아닌 검증셋에서 모델별(FP16 · INT8)로 정한다.
  • YOLOX를 더 큰 입력 크기로 재학습해 해상도 가설을 확인하고, 학습을 2–3회 반복해 편차를 확인한다.
  • NPU(Intel AI Boost)는 이번 측정에서 장치 오류로 실패해, 드라이버 업데이트 후 다시 측정한다.
