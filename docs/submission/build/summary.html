배터리 표면 식별 Vision AI

crack · scratch 탐지 → PASS · REVIEW · REJECT 판정

요약. Geti로 ATSS-MobileNetV2 · YOLOX-S · YOLOX-Tiny 학습, OpenVINO로 비교. 1차 테스트 mAP@50 최고는 ATSS 92.9%, INT8로 CPU 추론 2–4배 단축. 단, 1차 테스트 사진이 Geti 학습 데이터에 포함 → 1차 점수는 모델 간 비교용. 학습에 안 쓴 2차 세트에서 결함 셀 검출 47%.

1. 목표

  • 공개 데이터셋 + Geti 모델로 동작하는 검사 AI 구성
  • 판정: 신뢰도 ≥ 0.60 REJECT · 0.30–0.60 REVIEW · < 0.30 PASS
  • 가상 검사 라인 대시보드에서 실제 모델로 시연

2. 데이터와 방법

  • 데이터: Roboflow Battery Defect Inspection v8 (라벨 포함), 원본 1,531장, crack · scratch. 학습 3,214장(원본 1,072장 ×3 증강) · 검증 306장 · 테스트 153장.
  • Geti 업로드: v8 전체 3,673장(테스트 포함). Geti가 약 2,800장을 70/20/10으로 재분할 → 1차 테스트 일부가 학습에 쓰였을 가능성.
  • 정제: 학습 사진의 복사본 22장(dHash ≤ 8/256) 제거 → 1차 테스트 131장. ATSS mAP@50 93.3% → 92.9%. 촬영 세션 중복(153장 중 152장)은 남음.
  • 2차 세트: 같은 업로더의 Battery Defect Detection v2 중 기존과 겹치지 않는 45장(결함 30 · 정상 15), 학습 미사용.
  • 모델: ATSS-MobileNetV2(3.9M) · YOLOX-S(9M) · YOLOX-Tiny(5.06M) × FP16 · FP16+XAI · INT8.
  • 측정: 직접 만든 벤치마크(benchmark.py). 같은 사진 · 같은 기준. 속도는 Core Ultra 7 265K CPU, 사진 1장씩, 전처리·후처리 포함.
  • 한계: 탁상 촬영, 배경 3종(초록 매트 39 · 회색 54 · 나무 탁상 38장), 셀당 사진 1장.

6. 배운 것

  1. 테스트셋은 먼저 분리. 통째 업로드로 테스트가 학습에 섞임 · 복사본 · 세션 겹침.
  2. 큰 모델 ≠ 좋은 모델. 3.9M ATSS > 9M YOLOX-S.
  3. 최적화는 기준값과 함께. INT8 = 속도 ↑ · 신뢰도 ↓.
  4. 점수 ≠ 현장 성능. 92.9% → 새 환경 검출 47%, 기준값 조정으로 회복 불가.

7. 앞으로 할 일

  • 테스트셋 제외 후 재학습 · 재측정
  • 실제 스테이션 · 2차 세트 사진 추가 학습
  • 기준값을 검증셋에서 모델별(FP16 · INT8)로 결정
  • YOLOX 고해상도 재학습(해상도 가설 확인), 2–3회 반복 학습으로 편차 확인
  • NPU 재측정 (이번 측정은 장치 오류)
